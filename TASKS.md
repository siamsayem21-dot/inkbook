- **[Studio Timezone Capture 2/7] Timezone UX + Validation Design — VERIFIED (2026-08-16)**
  - Design/decision only, no code changed. Design:
  - **Single new shared helper, `lib/timezone.ts`:** exports `isValidIanaTimezone(value: unknown): value is string`, built on `Intl.supportedValuesOf('timeZone')` (417 canonical IANA identifiers, native/no dependency) as a `Set` for exact O(1) membership checking — no regex guessing, no address inference, nothing can slip through that isn't a real, canonical IANA zone name. This is the single validation source of truth both write paths (onboarding, Settings) will call — not a second timezone system, just one small shared predicate.
  - **Field type: native `<select>`, not free text.** Populated from the same `Intl.supportedValuesOf('timeZone')` list, alphabetically sorted. A native select constrained to valid options can never submit an invalid string by construction — server-side validation is still added as defense-in-depth (matches this codebase's existing pattern, e.g. `saveStudio()` already re-validates hex colors/font server-side even though the client UI already constrains them), but the UI itself makes "arbitrary invalid text" structurally impossible, not just discouraged. No new UI library, no custom searchable dropdown — a native `<select>` already supports type-to-jump in every real browser, which is enough for 417 options at "smallest clean UX" scope.
  - **Browser detection:** `Intl.DateTimeFormat().resolvedOptions().timeZone`, read client-side on mount only (never during SSR, since it must reflect the visiting browser's real environment). If the detected value is a valid IANA identifier (checked via the same shared helper), it becomes the select's initial value. **Clear fallback if detection fails or returns something not in the canonical list:** pre-select `'UTC'` instead — explicit, visible, matches the column's own existing safety-net default, and the owner can still freely change it before submitting either form.
  - **Never silently substitute a chosen value:** unlike `saveStudio()`'s existing soft-fallback pattern for colors/font (invalid input silently replaced with a safe default), timezone is stricter — an invalid/malformed value on either write path is **rejected with an explicit error**, never silently swapped to UTC or anything else, per the product rule's explicit "must not silently become the timezone."
